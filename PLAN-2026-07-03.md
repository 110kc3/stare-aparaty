## 2. `refresh-allegro.js` — Allegro price refresh via official API (~half day)

**Why now:** 10 of 15 affiliate cards are Allegro and `allegro-products.json` is hand-edited only. This replaced Amazon as the highest-ROI automation. Not in TODO.md yet — add it.

**Notes / design:**
- Register app at `developer.allegro.pl` → client-credentials OAuth flow (no user context needed for public offer data).
- Input: offer/product IDs parsed from the `url` fields in `scripts/allegro-products.json` (mixed `allegro.pl/produkt/…` and `business.allegro.pl/oferta/…` — handle both ID formats; verify each with grep before assuming).
- Output: write back `price`, `lastChecked`, optionally image — same shape the build already consumes, so `build-catalog.js` needs zero changes.
- Failure policy (mirror the PA-API spec in TODO.md): offer not found / no price → flag for manual replacement, never write a stale or empty price. Build guard (`assertRenderedOutput`) stays as backstop.
- Workflow: weekly cron, model on the disabled `refresh-amazon.yml.disabled` skeleton; secrets `ALLEGRO_CLIENT_ID` / `ALLEGRO_CLIENT_SECRET`; commit only on diff (same pattern as `discover-cameras.yml`).
- Tests: one `node:test` file for the ID-extraction + response-mapping helpers only. Run targeted: `node --test test/refresh-allegro.test.js --test-reporter=dot`, failures only.
- Open question to resolve before coding: whether the affiliate `redirect_url` wrapper needs regenerating when a price updates, or if links are price-independent (they should be — confirm once).
